## This repository (gluonify-plasma)
Maven parent (`io.gluonify.plasma:gluonify-plasma`, pom) + modules `sdk` (`gluonify-plasma-sdk`), `services` (`gluonify-plasma-services`: zero-configuration resolution, no dependency), `fermion-client`, `crystallon-client` (`gluonify-plasma-crystallon-client`), `testing` (`GluonifyTestServices`), `quarkus` (`@DefaultBean` producers) and `cli` (`gluonify` command, executable jar), each with its own README. The modules published for customers' applications are on Java 17 (`maven.compiler.release` 17, use nothing newer in them; checked by the build): `sdk`, `services`, `crystallon-client`, `testing`, `cli`; `quarkus` on 21, `fermion-client` on 25. `services` takes no dependency (internal JSON and HTTP, no reflection) and never logs a token. `gluonify.code-workspace` opens all the repositories. SDK content: `io.gluonify.plasma` (`AppSpec`, `Instance`, `DeployRequest`, `ws/Msg`, `store/Rendezvous`, `store/StoreCapability`, `wg/`, `crystallon/`: `RenderParams`, `RenderRequest`, `InlineRenderRequest`, `Issue`, `Check`, `ErrorBody`; `contracts/`: organization contracts, fingerprint, validation, `Pricing` valuation and the test set `sdk/src/test/resources/contracts/pricing-vectors.json`; `usage/`: closed catalogue of usage units). The signatures of `crystallon/` and of the client are a contract with the code that Crystallon generates: do not change them without updating gluonify-crystallon. Any change to a JSON contract ripples into higgs, strange, rup (reinstall plasma before recompiling the others). When adding a field to `AppSpec`/`Instance`/`DeployRequest`: keep compatibility constructors (the old calls are numerous) and update `Scheduler` (higgs).
