# gluonify-plasma-crystallon-client

HTTP client for **gluonify-crystallon** (PDF documents from a template) for customer applications: you designate a stored template by its name or its identifier, **or send the template with the request** (`inline`), pass a payload (record, bean or `Map`), and receive the PDF.

- **No configuration**: `CrystallonClient.create()` finds the address and the token by itself (platform, developer workstation after `gluonify login`, fake services in tests), through `gluonify-plasma-services`.
- **Java 17**, no CDI, no Quarkus: two mandatory dependencies, transitive and themselves dependency-free, the platform SDK (`gluonify-plasma-sdk`) and the service resolution (`gluonify-plasma-services`).
- **Jackson 2 or Jackson 3**, the application's own, detected at run time (`PayloadCodec.detect()`): neither is transitive.
- `java.net.http.HttpClient` transport created on the first call (native image compatible), timeout, maximum PDF size, Charm token.
- The code generated by the "Code" tab of the Crystallon editor (payload records and `<Name>Document` facade) builds on this module.

## Dependency

The version is the platform's (`0.6.0` at the time of writing; the repository carries its own version, the published one is set at publication). The Maven repository is served by gluonify-sea, with public read access.

```xml
<repositories>
  <repository>
    <id>gluonify</id>
    <url>https://images.gluonify.io/maven</url>
  </repository>
</repositories>

<dependency>
  <groupId>io.gluonify.plasma</groupId>
  <artifactId>gluonify-plasma-crystallon-client</artifactId>
  <version>0.6.0</version>
</dependency>
```

```kotlin
// Gradle (Kotlin DSL)
repositories {
    mavenCentral()
    maven("https://images.gluonify.io/maven")
}
dependencies {
    implementation("io.gluonify.plasma:gluonify-plasma-crystallon-client:0.6.0")
}
```

Jackson comes from the application (Quarkus 4: Jackson 3). With **Jackson 2**, also add `com.fasterxml.jackson.datatype:jackson-datatype-jsr310`: without it, Jackson 2 rejects `LocalDate` (the client registers the `JavaTimeModule` if it finds it). Jackson 2: 2.15 or later (records); verified with 2.17.2 and 2.22.2, and Jackson 3 with 3.1.4.

## Example

```java
CrystallonClient crystallon = CrystallonClient.create();                                   // no URL, no token to write

RenderedPdf pdf = crystallon.byName("Gluonify invoice").render(payload);                 // payload: record, bean or Map
Files.write(Path.of("invoice.pdf"), pdf.bytes());                                         // pdf.pages(), pdf.warnings(), pdf.pdfa()

RenderOptions fr = RenderOptions.builder().lang("fr").country("CH").currency("CHF").timezone("Europe/Zurich").build();
RenderedPdf swiss = crystallon.byId("3f2a…").version(7).render(payload, fr);              // a specific version of the template

Check check = crystallon.byName("Gluonify invoice").validate(payload);                     // no PDF: errors and warnings with their path
if (!check.valid()) check.errors().forEach(e -> log.warn("{} {} ({})", e.code(), e.message(), e.path()));
```

## A template sent with the request (`inline`)

For a template the application owns (a letter whose text lives in its code, a preset used without copying it into Crystallon), `inline(template)` needs nothing stored: the template travels with each request (`POST /v1/render`).

```java
InlineTemplate letter = crystallon.inline(Map.of(                       // the Crystallon template object: Map, record, bean or JsonNode
        "extends", "letter",                                            // a preset to customize
        "theme", Map.of("primary", "#005eb8")));
InlineTemplate quote = crystallon.inline("quote");                      // or the name of a preset: invoice, letter, quote

RenderOptions options = RenderOptions.builder().lang("fr").country("CH").pdfa(true).build();
RenderedPdf pdf = letter.render(letterData, options);                   // PDF/A-1B ; pdf.bytes(), pdf.pages(), pdf.warnings(), pdf.pdfa()
Check check = letter.validate(letterData, options);                     // POST /v1/render/validate: errors and warnings with their path in the template
```

- `template` is **a `String`: the name of a preset** (`GET /v1/presets` lists them), or **an object** serialized by the `PayloadCodec` (`Map`, record, bean, `JsonNode` of the codec's Jackson) that must produce a JSON object, optionally with `extends`. JSON written in a `String` is rejected (`IllegalArgumentException`: read the JSON into a `Map` or a `JsonNode` first); so is an object that does not serialize to a JSON object.
- **The template is frozen at creation**: `inline(…)` serializes it and keeps a private copy (modifying the `Map` afterwards changes nothing), and an unreadable template fails there, not at the first render. `InlineTemplate` is immutable and thread-safe, like `TemplateRef`; `inline` makes no network call. There is no `version(n)` (nothing is stored).
- Same `RenderOptions`, same errors (`CrystallonException` with the `path` of the problem in the template), same headers read, same PDF limit and same roles (`gluonify:crystallon:render`) as for a stored template.
- A `null` `data` is sent as `{}`, as for a stored template.
- **Interfero** (postal letters): `CrystallonClient.builder().baseUrl(…).tokens(CrystallonTokens.file(path)).json(Jackson3Codec.of(mapper)).build()`, then `client.inline(letterTemplate).render(data, RenderOptions.builder().lang(lang).country(country).pdfa(pdfa).build())`.
- Template and payload types in a native image: see "Native image".

## Default template parameters

A template (stored, preset or sent) may carry `params` at its root (`lang`, `country`, `currency`, `timezone`, `dateStyle`, `numberStyle`). For each parameter, **the request wins** (`RenderOptions`), otherwise **the template value**, otherwise **the server default**. `RenderOptions.DEFAULT` therefore requests no parameter: `render(payload)` uses those of the template. The `invoice` preset carries some (see the gluonify-crystallon README).

`byName` and `byId` make no network call: `TemplateRef` is immutable and can be kept. Without `version(n)`, Crystallon renders the current version of the template; with it, version `n` of its history (`?version=n`). `RenderOptions.DEFAULT` requests PDF/A-1B and leaves the parameters to the server; `pdfa(false)` gives the raw PDF. A `null` payload is sent as `{}` (a body without `data` would render the template's example).

## Configuration

**None**, with `CrystallonClient.create()`: the address and the token come from `GluonifyServices.endpoint("crystallon")` ([gluonify-plasma-services README](../services/README.md)):

| Where the application runs | Address | Token |
|---|---|---|
| in tests, after `GluonifyTestServices.start()` (or the `GLUONIFY_SERVICE_CRYSTALLON_URL` system property override) | the fake Crystallon | `GLUONIFY_CRYSTALLON_TOKEN` |
| on the platform (`GLUONIFY_ENVIRONMENT` present), `crystallon` in `uses` (inferred by Bup from this module's marker, or declared) | `GLUONIFY_SERVICE_CRYSTALLON_URL` injected | the application token (`GLUONIFY_CRYSTALLON_TOKEN_FILE`, re-read on every call) |
| on the developer workstation, after `gluonify login <zone>` | the public address from discovery (`https://adm.<zone>/crystallon`) | the developer token, renewed automatically |
| elsewhere | `GluonifyServicesException` saying what to do (`uses`, `gluonify login`, `GluonifyTestServices`) | |

A token failure during the application's lifetime (developer session expired, for example) becomes a `CrystallonException` with status 0 that keeps this message. `create(GluonifyServices)` takes a supplied resolution (tests); `builder().endpoint(GluonifyServices.endpoint("crystallon"))` keeps the resolution and lets you set the rest (mapper, timeout).

`CrystallonClient.fromEnvironment()` (unchanged, for existing applications) only reads the environment the platform injects:

| Variable | Role |
|---|---|
| `GLUONIFY_SERVICE_CRYSTALLON_URL` | Crystallon address; injected for `crystallon` in `uses`: Bup sets it automatically when this module is on the run-time classpath (marker `META-INF/gluonify/services/crystallon`), otherwise declare it. Absent: `IllegalStateException` saying what to do |
| `GLUONIFY_CRYSTALLON_TOKEN` | the Charm token itself |
| `GLUONIFY_CRYSTALLON_TOKEN_FILE` | otherwise, a file containing the token, re-read on every call |

Without environment code, with the builder:

| `CrystallonClient.builder()` method | Default | Role |
|---|---|---|
| `baseUrl(String \| URI)` | required | `http(s)://…` address, path prefix allowed, trailing slash ignored |
| `tokens(CrystallonTokens)` | `none()` | where the token comes from |
| `timeout(Duration)` | 30 s | timeout of a call, body reading included |
| `json(PayloadCodec)` | `PayloadCodec.detect()` | JSON gateway |
| `httpClient(HttpClient)` | created on the first call (HTTP/1.1) | HTTP client to reuse |
| `maxPdfBytes(long)` | 50 MB | beyond it, the PDF is rejected and reading stops |

## Tokens

Crystallon requires a Charm token with audience `gluonify-crystallon`; the role `gluonify:crystallon:render` is enough to render and validate (`…/render`, `…/render/validate`). The `convert` (conversion and merge) and `templates` (template management) roles are not used here.

| `CrystallonTokens` | Behavior |
|---|---|
| `none()` | no `Authorization` header |
| `fixed(token)` | fixed token (empty: `IllegalArgumentException`) |
| `file(path)` | read **on every call**, leading and trailing whitespace stripped; file missing or empty: no token; unreadable: `CrystallonException` (status 0) |
| `forwarding(supplier)` | the signed-in person's token, requested on every call (`null` or empty: no token) |
| `platform()` | the **application token** the platform provides to an application that has `crystallon` in `uses` (inferred by Bup, or declared): file from `GLUONIFY_CRYSTALLON_TOKEN_FILE`, dropped and renewed by the node agent (subject `app:<name>`, role `gluonify:crystallon:render`, 900 s), re-read on every call; variable absent: `IllegalStateException` saying so |
| `of(Endpoint)` | the tokens of a service resolved by `GluonifyServices` (what `create()` does); a failure of the source becomes a `CrystallonException` (status 0) |
| `fromEnvironment()` | `GLUONIFY_CRYSTALLON_TOKEN`, otherwise `GLUONIFY_CRYSTALLON_TOKEN_FILE`, otherwise `none()`; `fromEnvironment(Function<String,String>)` reads another source (MicroProfile Config…) |

The token is never written to an error message or a log. **Which one to choose**: `forwarding` when Crystallon must see the signed-in person (their roles, their organization); `platform()` for a call made on behalf of the application (scheduled task, webhook, message queue), since 2026-10-11: Higgs issues the token according to `uses`, Strange drops it in `/run/gluonify-tokens/crystallon.token` (read-only in the instance sandbox) and renews it before it expires. An application token carries Crystallon's default organization (`default`): templates of another organization are not visible to it.

## Errors

Every failure is a `CrystallonException` (unchecked): `status()` (HTTP status, **0 if there was no response**), `code()` (for example `CRYSTALLON-0014`), `getMessage()` (server message, in English), `path()` (location of the problem in the template JSON).

| Case | `status()` | `code()` |
|---|---|---|
| 400, 404, 422… with an `ErrorBody` | status received | server code (`path()` for template problems) |
| 401, 403 without a body (token missing, expired, without the `render` role) | 401 / 403 | `null` |
| proxy response (HTML, unreadable JSON) | status received | `null` |
| 2xx response that is not a PDF (`%PDF`), or PDF too large | status received | `null` |
| service unreachable, timeout, interrupted call | 0 | `null` |

A payload that Jackson cannot write throws `IllegalArgumentException` (programming error, no network call). No automatic retry: rendering has no side effect, but it is up to the application to decide.

## JSON: Jackson 2, Jackson 3, or your own

`PayloadCodec.detect()` picks `tools.jackson.databind.json.JsonMapper` (Jackson 3) if present, otherwise `com.fasterxml.jackson.databind.ObjectMapper` (Jackson 2); neither: `IllegalStateException` naming the artifacts to add. The mapper it creates writes dates in ISO-8601 (never as timestamps), `BigDecimal` in plain decimal notation (`1234.50`, never `1E+3`) and ignores unknown properties in responses.

To keep the application's mapper (modules, naming…):

```java
CrystallonClient.builder().baseUrl(url).json(Jackson3Codec.of(objectMapper)).build();   // or Jackson2Codec.of(mapper)
```

or implement `PayloadCodec` (two methods: `byte[] write(Object)` and `<T> T read(byte[], Class<T>)`), for example for another JSON engine.

## Quarkus (CDI)

The module brings neither `beans.xml` nor an extension: its classes are not beans. With the **`io.gluonify.plasma:gluonify-plasma-quarkus`** dependency, the application writes nothing: `@Inject CrystallonClient crystallon;` receives the client from `create()` with the application's `ObjectMapper` (`@Reserve` producer, created on first injection; see [quarkus/README.md](../quarkus/README.md)).

To call as the signed-in person, the application produces its own client, which replaces the default one:

```java
@Produces @Singleton
CrystallonClient crystallon(ObjectMapper mapper, JsonWebToken jwt) {     // Quarkus 4 tools.jackson.databind.ObjectMapper
    return CrystallonClient.builder().endpoint(GluonifyServices.endpoint("crystallon"))
            .tokens(CrystallonTokens.forwarding(jwt::getRawToken))        // outside a request, the supplier must return null
            .json(Jackson3Codec.of(mapper)).build();
}
```

## Native image

- The SDK records that Jackson reads or writes (`Check`, `Issue`, `ErrorBody`, `RenderRequest`, `InlineRenderRequest`, `RenderParams`) are declared in `META-INF/native-image/io.gluonify.plasma/gluonify-plasma-crystallon-client/reachability-metadata.json`, which `native-image` (hence Quarkus) reads by itself from the jar.
- **Payload types are the application's responsibility**: every record or bean passed to `render` / `validate`, **and every record or bean passed to `inline(…)` as a template**, must be registered for reflection (Quarkus: `@RegisterForReflection` on the type, or the component's `Reflection.java`; elsewhere: a `reachability-metadata.json` entry with `allDeclaredConstructors`, `allDeclaredMethods` and `allDeclaredFields`). An omission only breaks in native, at the first serialization (`UnsupportedFeatureError: Record components not available for record class …`), with no compilation error or JVM test failure.
- Verified in native (NIK 25, test program against a fake server, Jackson 3 then Jackson 2 with `jsr310`): JSON detection, rendering, validation, `ErrorBody` error, payload dates and `BigDecimal`; without the metadata file above, the first serialization fails as described.
- The `HttpClient` is never in a static field nor created at client construction; no static `Random`; the absent JSON library (Jackson 2 if the application only has Jackson 3, and vice versa) is never loaded.

## Routes called

| Call | Request |
|---|---|
| `byId(id).render(…)` | `POST {base}/v1/templates/{id}/render?pdfa=true\|false[&version=n]`, `Accept: application/pdf` |
| `byName(name).render(…)` | `POST {base}/v1/templates/by-name/{encoded name}/render?…` (the name is a path segment: space `%20`, `/` `%2F`) |
| `….validate(…)` | `POST …/render/validate[?version=n]`, `Accept: application/json` → `Check` |
| `inline(template).render(…)` | `POST {base}/v1/render?pdfa=true\|false`, `Accept: application/pdf`, body `{"template": …, "data": …, "params": …}` (`InlineRenderRequest`) |
| `inline(template).validate(…)` | `POST {base}/v1/render/validate`, `Accept: application/json` → `Check`, same body |

The body for a stored template is a JSON `RenderRequest` `{"data": …, "params": {…}}` (`params`: only the fields set in `RenderOptions`); the body for a sent template is an `InlineRenderRequest` `{"template": …, "data": …, "params": {…}}` (`template`: a string, the name of a preset, or an object). Render response: the PDF, and the `X-Crystallon-Pages`, `X-Crystallon-Warnings`, `X-Crystallon-PDFA` headers (`valid` or `invalid`) read into `RenderedPdf` (0 or `null` if missing).

The same tests run with five classpaths (surefire executions with `classpathDependencyExcludes`, the actual exclusion is verified): Jackson 2 and 3 present, Jackson 3 only, Jackson 2 only, Jackson 2 without `jsr310`, no Jackson (clear error, client usable with a supplied `PayloadCodec`).
