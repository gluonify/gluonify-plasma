Maven parent POM of the Gluonify components (`io.gluonify.plasma:gluonify-plasma`: Quarkus platform, versions) and shared libraries, nine modules:

| Module (`io.gluonify.plasma:…`) | Content | Java |

| `gluonify-plasma-fermion-client` (`fermion-client/`) | WebSocket client of gluonify-fermion (Quarkus, CDI); commands run in parallel | 26 |
| `gluonify-plasma-services` (`services/`) | **zero-configuration resolution** of a service (address and token): override, platform, developer workstation (zone discovery, token from `gluonify login`); no dependencies; [README](services/README.md) | 17 |
| `gluonify-plasma-crystallon-client` (`crystallon-client/`) | HTTP client of gluonify-crystallon: render a template to PDF by name or identifier, or a template sent with the request (`inline`); `CrystallonClient.create()` without configuration; no CDI, Jackson 2 or 3 detected at run time; [README](crystallon-client/README.md) | 17 |

| `gluonify-plasma-build-rules` (`build-rules/`) | the PMD ruleset checked by every Gluonify build (`gluonify/pmd/ruleset.xml`) and `quality_ratchet.py` (coverage and baseline ratchets): see [Quality gates](#quality-gates) | — |

`sdk`, `services`, `crystallon-client`, `testing`, `quarkus`, `mcp` and `cli` are the modules published for customer applications (Maven repository `https://images.gluonify.io/maven`): they compile for Java 17 (`maven.compiler.release` 17; `quarkus` and `mcp`: 21, the minimum of Quarkus 4), the parent and `fermion-client` for Java 25. The repository version `0.1.0-SNAPSHOT` is set at publication (it follows the platform version). The `gluonify.code-workspace` file opens all Gluonify repositories in VS Code (assumed to sit side by side).

```
mvn install      # installs the parent, the SDK and the clients into ~/.m2: prerequisite of gluonify-higgs, -strange, -rup
```

## Quality gates

Every repository that inherits this POM (and the ones that copy its configuration: gdown, calorimeter, synchrotron, source, gauge, sonar-rules, prism) fails `mvn verify` like a red test when its code breaks a rule or its coverage drops (decision of the user, 2026-10-19: 0 SonarQube issue, coverage above 95 %; rules in `gluonify-horizon/context/coding-standards.md`). The profile `gluonify-quality` is active in every module that has `src/main/java`:

| Check | Tool | Fails `mvn verify` when | Ratchet |
|---|---|---|---|
| Coverage | JaCoCo 0.8.14 (`prepare-agent`, `report` and `check` in `verify`, whole module) | line coverage < `gluonify.coverage.minimum` or branch coverage < `gluonify.coverage.branch.minimum` | each module sets its current level rounded down (default 0.95; the branch minimum defaults to the line minimum), raises it as tests are added, never lowers it; the report and the check are skipped with `-DskipTests` (no tests run, nothing to check: a native build's `mvn -DskipTests install` would otherwise read a stale `target/jacoco.exec`) |
| Coverage of `@QuarkusTest` | `quarkus-jacoco` (test scope) through the profile `gluonify-quarkus-coverage`, active in every module that has `src/main/resources/application.properties` (`-Dgluonify.quarkus-coverage.skip` turns it off): Quarkus transforms the bean classes, so without it a class reached only through a `@QuarkusTest` reads 0 % (gluonify-fermion: 38 % measured, 66 % real); surefire passes `quarkus.jacoco.data-file=target/jacoco.exec`, `reuse-data-file=true`, `report=false`, so the data lands in the file the JaCoCo report and check read | — (part of the coverage check) | — |
| Code rules | PMD 7.28.0 through maven-pmd-plugin 3.28.0, ruleset `gluonify/pmd/ruleset.xml` of `gluonify-plasma-build-rules`, main sources | any violation (all priorities) not listed in the module's `pmd-baseline.properties` | the baseline holds the debt of 2026-10-19 (`class=Rule,Rule`); a line is removed when the class is fixed, never added |
| Vue interfaces (`npm test`, also run by Quinoa where `quarkus.quinoa.run-tests=true`) | ESLint 9.39.5 flat config (`eslint.config.js`, the same file everywhere: `@eslint/js` recommended, `typescript-eslint` 8.71.0 strict, `eslint-plugin-vue` 10.11.1 essential, `eslint-plugin-sonarjs` 4.2.2 recommended) then Vitest with v8 coverage | a lint error not in `eslint-suppressions.json` (ESLint bulk suppressions, which also fail when a suppression is no longer needed: `npx eslint . --prune-suppressions`), or coverage below `coverage.thresholds` (lines, branches) in the Vite configuration | suppressions only shrink; thresholds at the current level rounded down |
| Python (gluonify-horizon, gluonify-plasma-python, `build-rules/` here) | ruff (`ruff.toml` or `pyproject.toml`), run by a unit test | any ruff violation outside the per-file debt of `ruff.toml` | the per-file debt only shrinks; plasma-python's `fail_under` is the coverage ratchet |
| Push to `main` | the pre-push hook of gluonify-horizon (`horizon knowledge hook install`) | a debt file grows (`pmd-baseline.properties`, `eslint-suppressions.json`), the documentation does not follow the code, or the pushed diff has a new SonarQube issue of any severity (analysed on quark against `main`; `skipped` stated when quark cannot judge) | — |

Rules (Sonar key → PMD rule): S1192 `AvoidDuplicateLiterals` (3 occurrences), S3776 `CognitiveComplexity` (above 15), S107 `ExcessiveParameterList` (above 7), S1186 `UncommentedEmptyMethodBody`, S108 `EmptyCatchBlock` (a comment allowed) and `EmptyControlStatement`, S2095/S2093 `CloseResource` and `UseTryWithResources`, unused code (`UnusedPrivateField`, `UnusedPrivateMethod`, `UnusedLocalVariable`, `UnusedFormalParameter`, `UnnecessaryImport`), S1659 `OneDeclarationPerLine`, S1168 `ReturnEmptyCollectionRatherThanNull`, S112 `AvoidThrowingRawExceptionTypes`, S106 `SystemPrintln`, S127 `AvoidReassigningLoopVariables`, S1612 `LambdaCanBeMethodReference`, and three XPath rules of ours: S3358 `NestedTernary`, S1845 `MembersDifferOnlyByCase`, S7467 `UnusedParameterNotUnnamed` (Java 22 and later). They are the rules our code broke most on quark's SonarQube on 2026-10-19 (11,742 Java issues: S1192 1,934, S3776 1,034, S1659 981, S3358 522, S1845 166…) that a local analyser can check; S6813 (field injection, allowed by the coding standards for Quarkus) and the rules without a PMD equivalent stay with SonarQube and the pre-push gate.

**Why PMD rather than Checkstyle**: the rules we break are semantic (cognitive complexity, unclosed resources, unused private members and parameters, duplicated literals per file) and PMD 7 has them with the same thresholds as Sonar, plus XPath rules on the typed AST for the ones it lacks; Checkstyle is a style checker (formatting, naming, Javadoc) without type resolution, and our formatting is not where the debt is. One analyser, one ruleset, one baseline format.

```
mvn verify                                            # tests, coverage check, PMD check
mvn verify -Djacoco.skip -Dpmd.skip                   # a scoped run (-Dtest=...) that cannot reach the module's coverage
# measure a module and regenerate its baseline (only to remove paid debt; the baseline never grows):
mvn verify -Dgluonify.coverage.minimum=0 -Dpmd.failOnViolation=false -Dgluonify.pmd.baseline=none
python3 build-rules/quality_ratchet.py coverage <module>   # current line and branch coverage, rounded down
python3 build-rules/quality_ratchet.py check <module>      # lists the baseline lines whose debt is paid
python3 -m unittest discover -s build-rules                # tests of the script, and ruff on it (ruff.toml)
```

A new rule goes into the ruleset (a new version of `gluonify-plasma-build-rules`), never a per-repository exclusion; a repository that adds the rule regenerates its baseline in the same change.

Overall documentation: [gluonify-codex](https://github.com/gluonify/gluonify-codex).

## Zero-configuration services (`gluonify-plasma-services`, since 2026-10-11)

An application writes **neither URL nor token** to reach a platform service: `CrystallonClient.create()`, the default `FermionTokenProvider` of fermion-client and the fermion URL (empty = resolved), and the beans of `gluonify-plasma-quarkus` all go through `GluonifyServices.endpoint("<service>")`, which resolves in this order: **override** (`GLUONIFY_SERVICE_<APP>_URL` as a system property, or as a variable outside the platform; token `GLUONIFY_<APP>_TOKEN[_FILE]`: tests), **platform** (`GLUONIFY_ENVIRONMENT`: address from `uses`, application token re-read on every call; service absent: "the platform did not grant the service …", i.e. an application not built by Bup with the SDK module, or a call outside the SDK without an explicit `uses`), **developer workstation** (zone from `~/.gluonify/config.json` written by `gluonify login <zone>`, public address from the document `https://<zone>/.well-known/gluonify` cached for 5 minutes, developer token `~/.gluonify/tokens/<zone>.json` renewed by the refresh token under lock), otherwise an error that says what to do (`gluonify login`, or `GluonifyTestServices` in tests). Files 0600, no token in any message or log, no static `HttpClient`. The contract of the discovery document (which Higgs will publish) is described in [services/README.md](services/README.md); the CLI in [cli/README.md](cli/README.md).

## Service markers: `uses` inferred at build (since 2026-10-11)

An application no longer writes `uses` by hand for the services it reaches through the SDK: each SDK module that talks to a platform service carries a **marker**, the resource `META-INF/gluonify/services/<service>` (the file name is the service name as written in `uses`; its content, the same name, is not read). After compilation the builder (gluonify-bup) unpacks the jars of the application's **runtime** classpath (Maven: `runtime` scope; Gradle: `runtimeClasspath`), reads the markers of the jars of the `io.gluonify.plasma` group and adds the services found, optional (`?crystallon`), to those declared by the build request or `gluonify.json`. The platform always sets the network and the service tokens before startup, from that list.

| Module | Marker | Why |
|---|---|---|
| `gluonify-plasma-crystallon-client` | `crystallon` | Crystallon HTTP client |
| `gluonify-plasma-fermion-client` | `fermion` | Fermion WebSocket client |
| `gluonify-plasma-quarkus` | none | its producers go through `crystallon-client`, which it brings in: the marker comes from that jar |
| `gluonify-plasma-services` | none | generic resolution, reaches no service by itself |
| `gluonify-plasma-testing` | **none, never** | test dependency: a service is never inferred from tests (and Bup only reads the runtime scope) |
| `gluonify-plasma-sdk`, `gluonify-plasma-cli` | none | JSON contracts; developer workstation tool |
| `gluonify-plasma-mcp` | none in `services/`; **`META-INF/gluonify/mcp`** | not a service: the capability "serves MCP tools", read by Bup to set `mcp: true` (never a `uses` entry), see below |

A new service client adds its marker (`src/main/resources/META-INF/gluonify/services/<service>`) and a `ServiceMarkerTest` that checks it; each module has its own (5 tests: the two clients have exactly their marker, `services`, `quarkus` and `testing` have none). An explicit `uses` remains necessary for a service reached outside the SDK (direct HTTP call to another application, Charm or Gdown by URL).

## MCP tools of an application (since 2026-10-18, app-mcp.md phase 1)

A customer's Quarkus application declares business tools that its organization's AI assistant calls through **Prism** (`app__<application>__<tool>`): dependency `gluonify-plasma-mcp`, `@McpTool(name, description, write)` on the public methods of a bean implementing `McpToolbox`, input schema derived from an arguments record (or given), `POST /mcp` in hand-written JSON-RPC 2.0 (`initialize`, `tools/list`, `tools/call`), the same wire as the Python SDK (`gluonify.fastapi.mcp`). Caller: the application-to-service Charm token verified by the application's `quarkus-oidc` plus an audience check (401 with `WWW-Authenticate: Bearer`), and only Prism's service token (`gluonify_kind=service`, `gluonify_app=prism`, property `gluonify.mcp.relay-app`; 403 otherwise); a `write` tool needs the role `gluonify:mcp:write` (403 before the tool runs). Limits and names shared with Prism in the SDK: `io.gluonify.plasma.mcp.McpContract` (tool name `[a-z][a-z0-9_]{0,40}`, 50 tools, schema 16 KiB, arguments 64 KiB, response 256 KiB, body 68 KiB, protocol versions, write role, marker). The SDK adds no endpoint (platform components that index it for `/q/usage`, Prism and Gauge with their own `/mcp`, are unaffected). Marker read by Bup: `META-INF/gluonify/mcp`, a capability distinct from the service markers. Responses are not marked `untrusted` by the application: Prism marks them. Details, properties and tests: [mcp/README.md](mcp/README.md).

Flag `mcp` (2026-10-18, app-mcp.md phase 2): additive optional `Boolean` field of `AppSpec` and `DeployRequest` (JSON `mcp`, compatibility constructors kept, `withMcp`, kept by the other copies, `AppSpec.mcpEnabled()`); `false` and absent are the same and stored as absent (stable equality and JSON of an old specification). `true`: the application serves MCP tools on `POST /mcp`; Bup sets it from the marker `META-INF/gluonify/mcp`; gluonify-higgs then blocks `/mcp` on the public ingress in PRD and lets Prism alone obtain the designation of an instance and the service tokens of audience `gluonify-<app>`. A single `Boolean` in the Raft state: no type to declare for native reflection.

| Property | Default | Role |
|---|---|---|
| `gluonify.mcp.audience` | `quarkus.oidc.token.audience`, else `gluonify-<quarkus.application.name>` | audience required in the `aud` claim of the caller's token |
| `gluonify.mcp.relay-app` | `prism` | the only application allowed to call `/mcp` (`gluonify_app` of a `gluonify_kind=service` token) |

## Provenance of executables and images (since 2026-10-11)

`io.gluonify.plasma.provenance` (specification: `gluonify-codex/provenance.md`): `ProvenanceStatement` (signed statement: application name, SHA-256 per architecture or `sha256:` digest of the image, key identifier, signing instant to the second; canonical bytes `gluonify-provenance 1` line by line, strict reading that requires the canonical bytes; `of(app, artifacts, image, keyId, at)` derives it from the deliverables of a specification) and `Provenance` (token `base64url(statement).base64url(signature)`, `sign`, `verify`: the statement is only read after the signature; `mismatch`: does the statement cover the name and the digests; `sameDeliverable`: do two specifications run the same bytes; reading of Ed25519 PEM PKCS#8 and SubjectPublicKeyInfo keys). JDK Ed25519, no dependency, Java 17. Field `provenance` (the token, optional) in `AppSpec` (with `withProvenance`, kept by `withOrganization` and `withDistributedQuotaMb`) and `DeployRequest`, compatibility constructors without it. A single string in the Raft state: no type to declare for native reflection. Fixed vector (key of test 1 of RFC 8032) in `ProvenanceTest`, signature identical to `openssl pkeyutl -sign -rawin`. Control: gluonify-higgs; signature: gluonify-bup. Pinning of image tags for the whole cluster (`provenance.md` § 8): additive messages `Msg.ImagePin` (`image`, `digest`), `Msg.State.pins` (digests resolved by the node, application -> pin) and `Msg.Desired.pins` (cluster pin of the node's applications); absent: empty, compatibility constructors kept. Digest of the service token policy: `Msg.Desired.tokenPolicy` (short digest of the effective catalogue and of the platform applications, sent with every desired state) and `Msg.ServiceTokens.policy` (the one under which the tokens of the reply were issued); absent (older control plane): `null`, compatibility constructors kept.

## Sleep mode (scale-to-zero): contract

x86-64 levels (`X86Levels`): additive field `AppSpec.artifactLevel` and `DeployRequest.artifactLevel` ("`amd64:v1`" to "`amd64:v4`", written by Bup with the level of its build; absent: v1, placed everywhere; validated in the constructor; `requiredX86Level(arch)`, `withArtifactLevel`, kept by the other copies) and `Msg.Host.x86Level` (processor level of the node, "v1" to "v4", announced by Strange with every state; null on arm64, macOS, Windows or for an old agent). `X86Levels.runs(nodeLevel, required)`: a node of unknown level is accepted (compatibility). Compatibility constructors kept; strings only: no new type for native reflection.

Python versions (`PythonVersions`, gluonify-codex/python.md § 3 bis.2): additive field `AppSpec.pythonVersion` and `DeployRequest.pythonVersion` (minor version "`3.13`" targeted by an archive of the `python` framework, written by Bup; absent: not a Python application; "`3.13.5`" reduced to "`3.13`", any other form rejected by the constructor; `withPythonVersion`, kept by the other copies) and `Msg.Host.pythonVersion` (minor version of the node's `python3`, announced by Strange; null: no python3 or old agent). `PythonVersions.runs(node, app)`: a Python application only goes to a node of the same minor version; a node without a version receives none; a non-Python application goes everywhere.

`SleepSpec` (additive field `sleep` of `AppSpec` and `DeployRequest`, compatibility constructors kept): `{enabled (false), freezeAfterSeconds (60), stopAfterSeconds (900, or freeze + 60 if the freeze exceeds 840), wakeTimeoutMs (5000), wake (absent: cluster values)}`; `SleepSpec.Wake` `{initialReplicas, additionalWhen {inflightPerReplica, heldRequests, slowWakeMs, ratePerReplica, stepReplicas, cooldownSeconds}}` (optional fields, bounds validated in the constructor, four-argument compatibility constructor); additive messages `Msg.InstanceReportRequest` / `Msg.InstanceReport` (report of an instance, including a sleeping one); values validated in the constructor (freeze 1 to 86400 s, stop greater than freeze, wake 100 to 60000 ms); `AppSpec.sleepEnabled()`; an `AppSpec` that enables the mode and is internal, has extra ports, a node role or `distributedLocks` is rejected. Additive messages: `Msg.Desired.sleeping` (instance -> `frozen` | `stopped`, absent = active: the desired sleep state of the node's instances, compatibility constructors kept) and `Msg.Slept` (agent acknowledgement: state reached, success, cause, duration). Full specification: [gluonify-codex/ARCHITECTURE.md](https://github.com/gluonify/gluonify-codex/blob/main/ARCHITECTURE.md), "Sleep mode".

## Organization (the customer): contract

`AppSpec.organization` and `DeployRequest.organization` (additive field, optional string, compatibility constructors kept): the organization the application belongs to, `[a-z0-9](?:[a-z0-9-]{0,38}[a-z0-9])?` (DNS label of 1 to 40 characters, the gluonify-charm pattern), validated in the constructor. Absent (`null`, field omitted from the JSON), the application is attached to nobody: readers display it as `_unassigned` (`Organizations.UNASSIGNED`, `AppSpec.organizationOrUnassigned()`), a value that is never stored (the pattern rejects it). A state or request without the field reads back identically. `AppSpec.withOrganization(org)` copies the specification. In `DeployRequest`, `organization: "_unassigned"` requests removal (`toSpec` then yields a specification without organization): the control plane thus distinguishes "absent" (stored organization kept) from "removed". Only a platform administrator sets the organization (rule enforced by gluonify-higgs); decision: [gluonify-codex/metering.md](https://github.com/gluonify/gluonify-codex/blob/main/metering.md) § 2.2.

`io.gluonify.plasma.Organizations`: `UNASSIGNED`, `CLAIM` (`org`, claim of the Charm tokens), `PATTERN`, `isValid`, `requireValid`, `orUnassigned`, `matches(filter, org)` (filter `null`: everything; `_unassigned`: without organization) and the four **customer roles**, valid in their organization only and never under the reserved `gluonify:` prefix:

| Role | Rights |
|---|---|
| `org:owner` | everything, including access and billing |
| `org:developer` | repositories, builds, deployments, configuration, DNS and API |
| `org:viewer` | read-only |
| `org:billing` | consumption and invoices |

### Customer tokens in the platform services: `CustomerAccess` (since 2026-10-18)

`io.gluonify.plasma.access.CustomerAccess` is the one rule by which a platform service accepts a **customer token** in addition to its platform tokens, so that a customer reaches the service's console on the customer origin (`app.<zone>`) within its organization ([gluonify-codex/subscriptions.md](https://github.com/gluonify/gluonify-codex/blob/main/subscriptions.md) § 3.2). Plain Java, no framework.

- **Customer token**: the `org` claim holds one valid organization identifier (a string, or a list of exactly one) **and** no role starts with `gluonify:`. A token with any `gluonify:` role is a platform token: the service treats it as before, and its `org:*` roles grant nothing through this rule.
- **Rights**: the service maps the customer roles to its own rights with a fixed `CustomerAccess.Table` written in its code (`Table.builder().grant("org:owner", ...)`), never with configuration; the builder refuses an unknown customer role and a right that is itself an `org:` role. Roles other than the four customer roles are ignored (a service right carried by a customer token is not taken from the token). A customer role the table does not grant (typically `org:billing`) gives an empty set: bounded to the organization, allowed nothing.
- **Organization**: `Customer.organization()`, the token's, never the request's; the service bounds every read and write to it (another organization's object is a 404).
- API: `recognise(orgClaim, roles, table)` → `Optional<Customer(organization, customerRoles, rights)>`, `organization(claim)`, `hasPlatformRole(roles)`, `PLATFORM_ROLE_PREFIX`. First user: gluonify-crystallon (`CustomerTokens`, a `SecurityIdentityAugmentor`).

## Common format of analysis findings

Package `io.gluonify.plasma.analysis` (SDK, Java 17; specification `gluonify-codex/analysis.md` § 3.6), shared by Bup, the future tracker and Prism. A finding contains **no sentence**: a stable rule code and arguments, which the interface translates (`analysis.rules.<code>.title|why|fix`).

- `Finding`: `v` (1), `id` (`sha256(kind|target|rule|location)` in hexadecimal, `Finding.idOf`, stable from one run to the next), `kind` (`FindingKind`: `native`, `deps`, `sonar`, `conformity`, `apitest`, `passive`, `zap`, `seo`), `rule` (`N-ELF`, `R-SECRET`, `GN04`, `gluonify:GN01`…; pattern `Finding.RULE`), `severity` (`Severity`: `blocker`, `critical`, `major`, `minor`, `info`), `blocking`, `location` (`Location`: **repository-relative** path, optional line; absolute path, `..` and backslash rejected), `args` (strings, at most 32, at most 1024 characters per value, never `null`), `ref` (`GHSA-…` advisory, Sonar key), `status` (`FindingStatus`: `open`, `accepted`, `fixed`). `Finding.open(...)` computes the identifier.
- `AnalysisSummary` (Bup's `BuildRecord.analysis`): `status` (`AnalysisStatus`: `skipped`, `ok`, `pending`, `unavailable`, `warning`, `blocked`; `worst` keeps the most severe), sections `native` (`NativeSummary`: architecture, size, gap, glibc, GraalVM, reflected types, resources, `Startup`), `deps` (`DepsSummary`, `Db`), `sonar` (`SonarSummary`), number of findings.
- `AnalysisReport`: `v`, `buildId`, `summary`, sorted `findings` (severity, blocking first, section, rule): content of `analysis.json` and of `GET /v1/builds/{id}/analysis`.

## `/q/usage` usage contract of the components (`gluonify-usage/1`, since 2026-10-17)

Package `io.gluonify.plasma.usage` (SDK, Java 17; plan [gluonify-codex/plans/usage-mcp.md](https://github.com/gluonify/gluonify-codex/blob/main/plans/usage-mcp.md) § 3 and § 5.2): what each platform component answers to `GET /q/usage` so that Higgs aggregates CPU and memory per application and per component, and the `usage` MCP tool of Gauge shows them. It is **not** a billing base (metering.md): everything that is not `measured` is indicative.

- `ProcessUsage`: pure reading (no dependency) of the current process: **cumulative** CPU in seconds (`utime + stime` from `/proc/self/stat`, never a percentage: the caller computes differences, a value that decreases is a reset), resident memory (`VmRSS`), threads, lifetime, heap if the runtime knows it; cgroup v2 of the process (`0::/path` of `/proc/self/cgroup` under `/sys/fs/cgroup`, root in a container: `memory.current`, `cpu.stat usage_usec`, `memory.max`). Injectable paths for tests; never throws: an absent or unreadable file (macOS, cgroup v1) yields an absent field, never an invented value.
- `UsageReport` (Jackson 3 records, absent fields omitted): `contract`, `component`, `version`, `instance`, `node`, `at` (ms), `process {cpuSecondsTotal, memoryBytes, memoryKind (rss|pss|cgroup), heapBytes, threads, uptimeSeconds}` (mandatory), `cgroup {cpuSecondsTotal, memoryBytes, memoryLimitBytes}` (optional), `attribution` (`none`, `measured`, `estimated`, `prorata`), `byApp [{app, uuid, cpuSeconds, memoryBytes, basis, unit, storageBytes}]` (empty if `none`; the application is identified by its UUID, the name is for display), `unattributedShare {cpuSeconds, memoryBytes}`, `storageBytes` (see "Occupied storage" below). `UsageReport.of(...)` assembles a valid reply: shares sorted (memory, then CPU), scaled down pro rata if their sum exceeds the process, unattributed share computed so that **Σ `byApp` + `unattributedShare` = `process`**. **Ceiling: 500 rows of real applications (`MAX_APPS`) plus a single `_other` row** (`OTHER`) that groups the rest and does not count in the 500; reply of at most 256 KiB (`UsageContract.MAX_BYTES`). Additive contract: a reader ignores unknown fields; `contract` only changes for a breaking change.
- `UsageContract.check(JsonNode | byte[])`: the validator, list of discrepancies in English (empty = conformant); used by the tests of all repositories and by `check-usage-contract.sh` (chamber). Rejects: missing mandatory field, unknown `attribution`, `none` with rows, `basis` outside `measured|estimated|prorata` (never `none` on a row), more than 500 rows or two `_other`, sum of shares different from the total, size exceeded; `storageBytes` that is not an integer ≥ 0, rows carrying `storageBytes` without the top-level total, or a rows' sum above it (messages of the storage checks in English).
- `UsageContributor` (CDI bean, optional): `byApp()` (or `byApp(process)`, which receives the process the resource has just measured, to split its totals pro rata without reading `/proc` again), `attribution()` (default `estimated`) and `storageBytes()` (default null: the total stored by the component, from a cache, reported even without rows) of a component that can attribute (gdown per database, rup per namespace, higgs per ingress…); reads counters or cached values, never a disk walk. Several beans: the weakest confidence wins; a failing bean brings the reply back to `none` without making it fail. Without a bean: `attribution: none`, valid state.
- `UsageResource` (`@Path("/q/usage")`, ready to use): **never anonymous** (401 without identity, 403 without role), `Cache-Control: no-store`, no secret or configuration value in the body.

**Explicit activation** (decision of 2026-10-17): the SDK is not a bean archive, the endpoint only appears in the component that asked for it; the `/q/` prefix stays blocked by the public ingress in PRD (Higgs' `ManagementPaths`).

| `quarkus.index-dependency.plasma-sdk.group-id` / `.artifact-id` | absent | `io.gluonify.plasma` / `gluonify-plasma-sdk`: enables discovery of `UsageResource` (and of the SDK beans) in this component |
| `gluonify.usage.component` | `quarkus.application.name` without the `gluonify-` prefix | the `component` field of the reply |

Roles: `gluonify:usage:read` (common, Higgs's) or `gluonify:<product>:usage:read` (direct operations call, `<product>` = the `component`); to be declared in each component's role configuration.

**Test jar** (`gluonify-plasma-sdk:test-jar`, managed in the parent POM): `UsageContractTests`, an abstract class that each component extends by providing `authorizedBody()`, `statusWithoutToken()`, `statusWithoutRole()` and **`secrets()`** (abstract on purpose: the sensitive values of its test configuration, at least one; an empty list fails the test, which would otherwise be tautological); six identical checks everywhere: conformant reply, 401 without token, 403 without role, bounded size, no secret in the body, and `storageIsConsistent` (since 2026-10-17: integers ≥ 0, rows' sum ≤ total; a component that stores data overrides `storesData()` to return true, and its report must then carry `storageBytes`).

**Occupied storage** (additive change of 2026-10-17, the contract stays `gluonify-usage/1`: a reader ignores unknown fields, an older report without it stays valid): optional `storageBytes` (`Long`, bytes) at the top level of the report (total stored by the component: disk, measured or from its last snapshot, never a disk walk in `/q/usage`) and on each `byApp` row (stored for that application). Absent (never `0` made up) when the component stores nothing. The rows' sum is at most the total: the remainder is stored but attributed to nobody (objects without an application). Storage never enters the CPU and memory split, and it is reported even with `attribution: none` (no row, e.g. Rup over a window without I/O: the total only). `UsageReport.of(..., shares, storageBytes)`: total kept without rows, rows beyond 500 add their storage to `_other` (a contributor's own `_other` row joins it), a total below the rows' sum is raised to it, no total and rows with storage: their sum. `UsageResource` sums the `storageBytes()` of the contributors. Example:

```json
{"contract":"gluonify-usage/1","component":"rup","at":1760700000000,

 "attribution":"prorata",
 "byApp":[{"app":"shop","cpuSeconds":8.0,"memoryBytes":178956970,"basis":"prorata","storageBytes":5368709120},
          {"app":"blog","cpuSeconds":4.0,"memoryBytes":89478485,"basis":"prorata","storageBytes":1073741824}],
 "unattributedShare":{"cpuSeconds":108.0,"memoryBytes":1},
 "storageBytes":7516192768}
```

## gluonify-fermion protocol (BPMN workflows and DMN rules)

Package `io.gluonify.plasma.fermion`: the WebSocket contract between an application node and gluonify-fermion. `FermionMsg` (sealed interface, field `t`): `Auth` (first message: Charm token of audience `gluonify-fermion` and protocol version, never in the URL), `Hello` (skills and workflows used, OpenAPI address), `Start` (submit a workflow; optional `organization`, the organization of the execution set by a platform node), `Command` (run a task: `action` = the skill, optional `stepId` = the BPMN node id, to tell two steps of the same skill apart), `Result` (success or failure with machine-readable `errorKind`; carries `stepId`, `Result.ok(command, …)` and `Result.failure(command, …)` do it), `Progress` (heartbeat of a running task: `correlationId`, `action`, `stepId`, optional `message` and optional structured `data`, a map kept by fermion in the execution's timeline; `Progress.of(command, message[, data])`; fermion pushes back the result deadline and does not resend the task; an earlier fermion logs a read error and ignores it), `Done` (fermion → the node that submitted a workflow, at its successful end: `correlationId`, `globalTransactionId`, `workflow`, final `payload`), `Cancel` (fermion → the node a task is assigned to: `correlationId`, `stepId`, `action`, `reason`, `resumable`; the node answers with a `Result` failure of kind `Cancel.INTERRUPTED` = `interrupted`), `Error`. `SkillDescriptor.expectedDuration` (optional, ISO-8601: `PT2H`, `P7D`) announces the longest silence allowed for a skill; `SkillDescriptor.requires` (optional, sorted map) the slots of the node's capacity one task holds. `Hello.capacity` (optional `NodeCapacity`: `slots` per resource name, sorted, and `closed` windows `NodeCapacity.Window(from, to, days, zone)`, daily `HH:mm-HH:mm` crossing midnight when `to` is not after `from`, `from == to` = the whole day, `days` = the days the window starts on, zone `Europe/Paris` by default; text form `[MON,TUE ]HH:mm-HH:mm`) lets fermion place by capacity and time. `Done`, `Cancel`, `data`, `capacity` and `requires` were added without changing `PROTOCOL` (1): empty values are left out of the JSON, every record ignores unknown fields. The frames are pinned by the fixtures `sdk/src/test/resources/fermion/*.json` (`FermionContractTest` writes each back byte for byte; gluonify-plasma-python's `fermion.py` reads the same files). The `organization` and `stepId` fields are optional in both directions: a node that ignores them (gluonify-interfero) stays compatible. Related types: `SkillDescriptor`, `WorkflowDescriptor`, `SkillParam`, `Translation`, `Language` (en, fr, es, it, de). The SDK only contains the contract; the client is the `fermion-client` module (`gluonify-plasma-fermion-client`, package `io.gluonify.plasma.fermion.client`): Quarkus WebSockets Next connection with Charm token in the `Auth` frame, scheduled reconnection with a fresh connector on every attempt, bounded queue of `Start` during an outage, SPI `SkillHandler` (`requires()` slots, `onCancel(context, cancel)` called on another thread when fermion cancels the running task, default no-op; a `Cancel` for a task that does not run here is acknowledged at once as `interrupted`) / `SkillHandlerRegistry` / `TaskContext` (`progress(Map)` sends a structured event) / `WorkflowUsage`, `FermionClient.onWorkflowDone((correlationId, payload) -> …)` next to `onWorkflowError`; see `fermion-client/README.md` (configuration `gluonify.fermion.client.*`). The types must be listed in the consumer's `Reflection.java` (native).

## Deprecated signatures (since 0.7.2)

Grouped signatures replace the long parameter lists of the published SDK; the old ones stay for one version, marked `@Deprecated(forRemoval = true)`, and delegate to the new ones. They are removed in the version after 0.7.2.

| Deprecated | Use |
|---|---|
| `GzipSignature.sign(unsigned, out, name, arch, version, sequence, expires, key)` | `sign(unsigned, out, new GzipSignature.Signing(name, arch, version, sequence, expires), key)` |
| `TrustedKeys.verify(manifest, sig, sig2, parser, minSequence, now)` | `verify(new TrustedKeys.Signed(manifest, sig, sig2), parser, minSequence, now)` |
| `TrustedKeys.applyRollover(manifest, sig, sig2, rollover, rolloverSig, rolloverSig2, highestSeen, now)` | `applyRollover(new TrustedKeys.Signed(manifest, sig, sig2), new TrustedKeys.Announcement(rollover, rolloverSig, rolloverSig2), highestSeen, now)` |
| `new UsageMeter(service, replica, node, version, env, maxKeys, clock, seqs)` | `new UsageMeter(new UsageMeter.Identity(service, replica, node, version, env), maxKeys, clock, seqs)` |
| `UsageMeter.add(at, subject, unit, dims, quantity, internal, onBehalfOf)` | `add(at, subject, new UsageMeter.Measure(unit, dims, quantity), new UsageMeter.Attribution(internal, onBehalfOf))` |
| `UsageEmitter.fromEnvironment(Function<String, String>, timeout)` | `fromEnvironment(UnaryOperator<String>, timeout)` |
| `DeveloperConfig.home(Function<String, String>, Function<String, String>)` | `home(UnaryOperator<String>, UnaryOperator<String>)` |
| `GluonifyServices.Builder.environment(Function<String, String>)` / `properties(Function<String, String>)` | the same methods taking a `UnaryOperator<String>` |
