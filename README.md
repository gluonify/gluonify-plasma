# Gluonify Plasma — POM parent, SDK et clients

POM parent Maven des composants Gluonify (`io.gluonify.plasma:gluonify-plasma` : plateforme Quarkus, versions) et bibliothèques partagées, sept modules :

| Module (`io.gluonify.plasma:…`) | Contenu | Java |
|---|---|---|
| `gluonify-plasma-sdk` (`sdk/`) | contrats JSON : `AppSpec`, `Instance`, messages WebSocket entre nœuds et control-plane, hachage de rendez-vous, capacités de stockage, manifeste signé, protocole de fermion, records de Crystallon (`io.gluonify.plasma.crystallon`), format commun des constats d'analyse (`io.gluonify.plasma.analysis`), contrats des organisations et catalogue des unités d'usage (`io.gluonify.plasma.contracts`, `io.gluonify.plasma.usage`), contrat d'usage `/q/usage` des composants (`ProcessUsage`, `UsageReport`, `UsageContract`, `UsageContributor`, `UsageResource`) | 17 |
| `gluonify-plasma-fermion-client` (`fermion-client/`) | client WebSocket de gluonify-fermion (Quarkus, CDI) ; commandes exécutées en parallèle | 26 |
| `gluonify-plasma-services` (`services/`) | **résolution sans configuration** d'un service (adresse et jeton) : surcharge, plateforme, poste du développeur (découverte de la zone, jeton de `gluonify login`) ; aucune dépendance ; [README](services/README.md) | 17 |
| `gluonify-plasma-crystallon-client` (`crystallon-client/`) | client HTTP de gluonify-crystallon : rendre en PDF un modèle par son nom ou son identifiant, ou un modèle envoyé avec la demande (`inline`) ; `CrystallonClient.create()` sans configuration ; sans CDI, Jackson 2 ou 3 détecté à l'exécution ; [README](crystallon-client/README.md) | 17 |
| `gluonify-plasma-testing` (`testing/`) | `GluonifyTestServices` : faux Crystallon en mémoire pour les tests des applications ; [README](testing/README.md) | 17 |
| `gluonify-plasma-quarkus` (`quarkus/`) | producteurs CDI `@DefaultBean` (`CrystallonClient`) : rien à écrire dans une application Quarkus ; [README](quarkus/README.md) | 21 |
| `gluonify-plasma-cli` (`cli/`) | la commande `gluonify` (jar exécutable) : `login <zone>` dans le navigateur (PKCE), `logout`, `status`, `token <service>` ; [README](cli/README.md) | 17 |

`sdk`, `services`, `crystallon-client`, `testing`, `quarkus` et `cli` sont les modules publiés pour les applications des clients (dépôt Maven `https://images.gluonify.io/maven`) : ils se compilent pour Java 17 (`maven.compiler.release` 17 ; `quarkus` : 21, le minimum de Quarkus 4), le parent et `fermion-client` pour Java 25. La version `0.1.0-SNAPSHOT` du dépôt est fixée à la publication (elle suit celle de la plateforme). Le fichier `gluonify.code-workspace` ouvre dans VS Code tous les dépôts Gluonify (supposés côte à côte).

```
mvn install      # installe le parent, le SDK et les clients dans ~/.m2 : prérequis de gluonify-higgs, -strange, -rup
```

Documentation d'ensemble : [gluonify-codex](https://github.com/gluonify/gluonify-codex).

## Services sans configuration (`gluonify-plasma-services`, depuis le 2026-10-11)

Une application n'écrit **ni URL ni jeton** pour joindre un service de la plateforme : `CrystallonClient.create()`, le `FermionTokenProvider` par défaut de fermion-client et l'URL de fermion (vide = résolue), et les beans de `gluonify-plasma-quarkus` passent par `GluonifyServices.endpoint("<service>")`, qui résout dans cet ordre : **surcharge** (`GLUONIFY_SERVICE_<APP>_URL` en propriété système, ou en variable hors de la plateforme ; jeton `GLUONIFY_<APP>_TOKEN[_FILE]` : tests), **plateforme** (`GLUONIFY_ENVIRONMENT` : adresse de `uses`, jeton d'application relu à chaque appel ; service absent : « the platform did not grant the service … », c'est-à-dire application non construite par Bup avec le module du SDK, ou appel hors du SDK sans `uses` explicite), **poste du développeur** (zone de `~/.gluonify/config.json` écrite par `gluonify login <zone>`, adresse publique du document `https://<zone>/.well-known/gluonify` gardé 5 minutes, jeton du développeur `~/.gluonify/tokens/<zone>.json` renouvelé par le jeton de rafraîchissement sous verrou), sinon une erreur qui dit quoi faire (`gluonify login`, ou `GluonifyTestServices` en test). Fichiers 0600, aucun jeton dans un message ni un journal, aucun `HttpClient` statique. Le contrat du document de découverte (que Higgs publiera) est décrit dans [services/README.md](services/README.md) ; la CLI dans [cli/README.md](cli/README.md).

## Bolt de gDown pour les applications : contrat (depuis le 2026-10-13)

`io.gluonify.plasma.GdownBolt` : port `7687`, clé `gdown:bolt` de la table des services de l'état désiré, variables `GLUONIFY_GDOWN_BOLT_URL` et `GLUONIFY_GDOWN_CA_FILE`
(réservées : `AppSpec` les refuse dans `env` et `generated`), secret public `GLUONIFY_INTERNAL_CA_CERT`, fichier `/run/gluonify-ca/gluonify-internal-ca.pem`. Conception :
`gluonify-gdown/paas.md` §9. Le SDK Java n'injecte rien de plus : une application lit ces variables (pilote Neo4j, Neo4j-OGM, Spring Data Neo4j).

## Marqueurs de service : `uses` déduit au build (depuis le 2026-10-11)

Une application n'écrit plus `uses` à la main pour les services qu'elle joint par le SDK : chaque module du SDK qui parle à un service de la plateforme porte un **marqueur**, la ressource `META-INF/gluonify/services/<service>` (le nom du fichier est le nom du service tel qu'écrit dans `uses` ; son contenu, le même nom, n'est pas lu). Le builder (gluonify-bup) recopie après la compilation les jars du chemin de classes **d'exécution** de l'application (Maven : portée `runtime` ; Gradle : `runtimeClasspath`), lit les marqueurs des jars du groupe `io.gluonify.plasma` et ajoute les services trouvés, facultatifs (`?crystallon`), à ceux que déclarent la requête de build ou `gluonify.json`. La plateforme fixe toujours le réseau et les jetons de service avant le démarrage, d'après cette liste.

| Module | Marqueur | Pourquoi |
|---|---|---|
| `gluonify-plasma-crystallon-client` | `crystallon` | client HTTP de Crystallon |
| `gluonify-plasma-fermion-client` | `fermion` | client WebSocket de Fermion |
| `gluonify-plasma-quarkus` | aucun | ses producteurs passent par `crystallon-client`, qu'il apporte : le marqueur vient de ce jar |
| `gluonify-plasma-services` | aucun | résolution générique, ne joint aucun service par elle-même |
| `gluonify-plasma-testing` | **aucun, jamais** | dépendance de test : un service n'est jamais déduit des tests (et Bup ne lit que la portée d'exécution) |
| `gluonify-plasma-sdk`, `gluonify-plasma-cli` | aucun | contrats JSON ; outil du poste du développeur |

Un nouveau client de service ajoute son marqueur (`src/main/resources/META-INF/gluonify/services/<service>`) et un `ServiceMarkerTest` qui le vérifie ; chaque module a le sien (5 tests : les deux clients ont exactement leur marqueur, `services`, `quarkus` et `testing` n'en ont aucun). `uses` explicite reste nécessaire pour un service joint hors du SDK (appel HTTP direct vers une autre application, Charm ou Gdown par URL).

## Provenance des exécutables et des images (depuis le 2026-10-11)

`io.gluonify.plasma.provenance` (spécification : `gluonify-codex/provenance.md`) : `ProvenanceStatement` (déclaration signée : nom de l'application, SHA-256 par architecture ou empreinte `sha256:` de l'image, identifiant de clé, instant de signature à la seconde ; octets canoniques `gluonify-provenance 1` ligne à ligne, lecture stricte qui exige les octets canoniques ; `of(app, artifacts, image, keyId, at)` la tire des livrables d'une spécification) et `Provenance` (jeton `base64url(déclaration).base64url(signature)`, `sign`, `verify` : la déclaration n'est lue qu'après la signature ; `mismatch` : la déclaration couvre-t-elle le nom et les empreintes ; `sameDeliverable` : deux spécifications exécutent-elles les mêmes octets ; lecture des clés Ed25519 PEM PKCS#8 et SubjectPublicKeyInfo). Ed25519 du JDK, aucune dépendance, Java 17. Champ `provenance` (le jeton, facultatif) dans `AppSpec` (avec `withProvenance`, conservé par `withOrganization` et `withDistributedQuotaMb`) et `DeployRequest`, constructeurs de compatibilité sans lui. Une chaîne seulement dans l'état Raft : aucun type à déclarer pour la réflexion native. Vecteur fixe (clé du test 1 de la RFC 8032) dans `ProvenanceTest`, signature identique à `openssl pkeyutl -sign -rawin`. Contrôle : gluonify-higgs ; signature : gluonify-bup. Épingle des étiquettes d'image pour tout le cluster (`provenance.md` § 8) : messages additifs `Msg.ImagePin` (`image`, `digest`), `Msg.State.pins` (empreintes résolues par le nœud, application → épingle) et `Msg.Desired.pins` (épingle du cluster des applications du nœud) ; absents : vides, constructeurs de compatibilité conservés. Empreinte de la politique des jetons de service : `Msg.Desired.tokenPolicy` (empreinte courte du catalogue effectif et des applications de la plateforme, envoyée à chaque état désiré) et `Msg.ServiceTokens.policy` (celle sous laquelle les jetons de la réponse ont été émis) ; absentes (control-plane plus ancien) : `null`, constructeurs de compatibilité conservés.

## Amorçage à distance : manifeste signé et catalogue de tâches

`io.gluonify.plasma.release` : `ReleaseManifest` (manifeste de version : version, séquence, expiration, un artefact par composant et architecture, format ligne à ligne relu à l'identique), `ReleaseVerifier` (signature Ed25519, expiration, séquence anti-retour, SHA-256), `ReleaseSigner`
(production et signature, utilisé par les tests ; la production réelle passe par `gluonify-chamber/bin/sign-release.sh`) et `Gzip` (fichiers gzip des versions : règle `.gz` hors `.tar.gz` = fichier unique compressé, nom décompressé sans `.gz` ; `gunzip` en flux borné par un plafond de taille et un rapport de décompression de 100, CRC-32, taille et octets en trop vérifiés ; le gzip ne remplace pas le SHA-256 du manifeste, vérifié d'abord sur le `.gz`) ; `ReleaseManifest.Artifact.gzipped()/plainFile()` ; le format du manifeste est inchangé (aucun champ ajouté, les noms en `.gz` sont des noms simples valides) ; `ReleaseSigner.build` reconnaît `<composant>-linux-<arch>.gz` ; et `TaskCatalogue` (le **catalogue fermé** de tâches avec ses motifs de paramètres, appliqué par le control-plane et par le nœud). Rotation de la clé de publication : `KeyRollover` (annonce `rollover.json` de la nouvelle clé, format canonique, séparée du manifeste dont le format 0.1.0 reste inchangé) et `TrustedKeys` (ensemble de clés acceptées, fichier `release.keys`, règles d'acceptation d'une annonce `applyRollover`, fin de rotation `finish`, refus après la date de bascule) ; tâche `rotate-release-key` du catalogue. Messages WebSocket additifs : `Msg.Startup` (temps de démarrage d'une instance, joint à `Msg.State.startups` : `prepare`, `listen`, `ready`, `total`, historique borné, compteurs), `Msg.BootstrapHello`,
`BootstrapAccepted`, `BootstrapDone`, `TaskRun`, `TaskProgress`, `TaskResult`, `TaskCancel`. Spécification : [gluonify-codex/docs/BOOTSTRAP.md](https://github.com/gluonify/gluonify-codex/blob/main/docs/BOOTSTRAP.md).

## Mode endormi (scale-to-zero) : contrat

Niveaux x86-64 (`X86Levels`) : champ additif `AppSpec.artifactLevel` et `DeployRequest.artifactLevel` (« `amd64:v1` » à « `amd64:v4` », écrit par Bup avec le niveau de son build ; absent : v1, placé partout ; validé au constructeur ; `requiredX86Level(arch)`, `withArtifactLevel`, conservé par les autres copies) et `Msg.Host.x86Level` (niveau du processeur du nœud, « v1 » à « v4 », annoncé par Strange à chaque état ; null sur arm64, macOS, Windows ou pour un ancien agent). `X86Levels.runs(niveauDuNœud, exigé)` : un nœud de niveau inconnu est accepté (compatibilité). Constructeurs de compatibilité conservés ; des chaînes seulement : aucun type nouveau pour la réflexion native.

Versions de Python (`PythonVersions`, gluonify-codex/python.md § 3 bis.2) : champ additif `AppSpec.pythonVersion` et `DeployRequest.pythonVersion` (version mineure « `3.13` » visée par une archive du framework `python`, écrite par Bup ; absente : pas une application Python ; « `3.13.5` » ramené à « `3.13` », toute autre forme refusée au constructeur ; `withPythonVersion`, conservée par les autres copies) et `Msg.Host.pythonVersion` (version mineure du `python3` du nœud, annoncée par Strange ; null : pas de python3 ou ancien agent). `PythonVersions.runs(nœud, appli)` : une application Python ne va que sur un nœud de la même version mineure ; un nœud sans version n'en reçoit aucune ; une application non Python va partout.

`SleepSpec` (champ additif `sleep` de `AppSpec` et `DeployRequest`, constructeurs de compatibilité conservés) : `{enabled (false), freezeAfterSeconds (60), stopAfterSeconds (900, ou gel + 60 si le gel dépasse 840), wakeTimeoutMs (5000), wake (absent : valeurs du cluster)}` ; `SleepSpec.Wake` `{initialReplicas, additionalWhen {inflightPerReplica, heldRequests, slowWakeMs, ratePerReplica, stepReplicas, cooldownSeconds}}` (champs facultatifs, bornes validées au constructeur, constructeur de compatibilité à quatre arguments) ; messages additifs `Msg.InstanceReportRequest` / `Msg.InstanceReport` (rapport d'une instance, y compris endormie) ; valeurs validées au constructeur (gel 1 à 86400 s, arrêt supérieur au gel, réveil 100 à 60000 ms) ; `AppSpec.sleepEnabled()` ; un `AppSpec` qui active le mode et qui est interne, a des ports supplémentaires, un rôle de nœud ou `distributedLocks` est refusé. Messages additifs : `Msg.Desired.sleeping` (instance -> `frozen` | `stopped`, absente = active : l'état de sommeil voulu des instances du nœud, constructeurs de compatibilité conservés) et `Msg.Slept` (accusé de l'agent : état atteint, succès, cause, durée). Spécification complète : [gluonify-codex/ARCHITECTURE.md](https://github.com/gluonify/gluonify-codex/blob/main/ARCHITECTURE.md), « Mode endormi ».

## Organisation (le client) : contrat

`AppSpec.organization` et `DeployRequest.organization` (champ additif, chaîne facultative, constructeurs de compatibilité conservés) : l'organisation à laquelle appartient l'application, `[a-z0-9](?:[a-z0-9-]{0,38}[a-z0-9])?` (étiquette DNS de 1 à 40 caractères, le motif de gluonify-charm), validée au constructeur. Absente (`null`, champ omis dans le JSON), l'application n'est rattachée à personne : les lecteurs l'affichent `_unassigned` (`Organizations.UNASSIGNED`, `AppSpec.organizationOrUnassigned()`), valeur qui n'est jamais enregistrée (le motif la refuse). Un état ou une requête sans le champ se relit à l'identique. `AppSpec.withOrganization(org)` copie la spécification. Dans `DeployRequest`, `organization: "_unassigned"` demande le retrait (`toSpec` donne alors une spécification sans organisation) : le control-plane distingue ainsi « absente » (organisation enregistrée conservée) de « retirée ». Seul un administrateur de la plateforme fixe l'organisation (règle appliquée par gluonify-higgs) ; décision : [gluonify-codex/metering.md](https://github.com/gluonify/gluonify-codex/blob/main/metering.md) § 2.2.

`io.gluonify.plasma.Organizations` : `UNASSIGNED`, `CLAIM` (`org`, revendication des jetons Charm), `PATTERN`, `isValid`, `requireValid`, `orUnassigned`, `matches(filtre, org)` (filtre `null` : tout ; `_unassigned` : sans organisation) et les quatre **rôles des clients**, valables dans leur organisation seulement et jamais sous le préfixe réservé `gluonify:` :

| Rôle | Droits |
|---|---|
| `org:owner` | tout, accès et facturation compris |
| `org:developer` | dépôts, builds, déploiements, configuration, DNS et API |
| `org:viewer` | lecture seule |
| `org:billing` | consommation et factures |

## Format commun des constats d'analyse

Paquet `io.gluonify.plasma.analysis` (SDK, Java 17 ; spécification `gluonify-codex/analysis.md` § 3.6), partagé par Bup, le futur tracker et Prism. Un constat ne contient **aucune phrase** : un code de règle stable et des arguments, que l'interface traduit (`analysis.rules.<code>.title|why|fix`).

- `Finding` : `v` (1), `id` (`sha256(kind|cible|règle|emplacement)` en hexadécimal, `Finding.idOf`, stable d'un passage à l'autre), `kind` (`FindingKind` : `native`, `deps`, `sonar`, `conformity`, `apitest`, `passive`, `zap`, `seo`), `rule` (`N-ELF`, `R-SECRET`, `GN04`, `gluonify:GN01`… ; motif `Finding.RULE`), `severity` (`Severity` : `blocker`, `critical`, `major`, `minor`, `info`), `blocking`, `location` (`Location` : chemin **relatif au dépôt**, ligne facultative ; chemin absolu, `..` et barre oblique inverse refusés), `args` (chaînes, 32 au plus, 1024 caractères au plus par valeur, jamais `null`), `ref` (avis `GHSA-…`, clé Sonar), `status` (`FindingStatus` : `open`, `accepted`, `fixed`). `Finding.open(...)` calcule l'identifiant.
- `AnalysisSummary` (le `BuildRecord.analysis` de Bup) : `status` (`AnalysisStatus` : `skipped`, `ok`, `pending`, `unavailable`, `warning`, `blocked` ; `worst` garde le plus grave), volets `native` (`NativeSummary` : architecture, taille, écart, glibc, GraalVM, types réfléchis, ressources, `Startup`), `deps` (`DepsSummary`, `Db`), `sonar` (`SonarSummary`), nombre de constats.
- `AnalysisReport` : `v`, `buildId`, `summary`, `findings` triés (sévérité, bloquants d'abord, volet, règle) : contenu d'`analysis.json` et de `GET /v1/builds/{id}/analysis`.
- `AnalysisUnits` : noms des unités de mesure des analyses (`bup.analysis.runs{kind}`, `bup.analysis.seconds`, `bup.apitests.*`, `bup.jobs.seconds{kind}`, `tracker.checks.runs{kind}`, `tracker.seo.*`, `tracker.zap.*`) et valeurs énumérées des dimensions (`metering.md` § 3.1).

Champs absents omis du JSON, propriétés inconnues ignorées à la lecture, `v`, `blocking` et le nombre de constats en types objets (un document qui les omet se relit : Jackson 3 refuse sinon un primitif absent). Image native : les types sont déclarés dans `META-INF/native-image/io.gluonify.plasma/gluonify-plasma-sdk/reachability-metadata.json` du SDK. Tests : `AnalysisFormatTest` (11).

## Contrats des organisations : records, validation, empreinte, valorisation (phase C0)

Paquets `io.gluonify.plasma.contracts` et `io.gluonify.plasma.usage` (SDK, Java 17 ; spécification [gluonify-codex/contracts.md](https://github.com/gluonify/gluonify-codex/blob/main/contracts.md)), partagés par Higgs (stockage Raft et contrôles), le calorimètre (valorisation) et Prism (lecture et estimation).

- `Organization` : `id` (motif de `Organizations`, immuable ; `_default` = pseudo-organisation du contrat par défaut), `name` (1 à 120 caractères), `status` (`active`, `suspended`, `archived`), `externalRef`, `createdAt`, `createdBy`, `versions` (jamais `null`).
- `ContractVersion` : `version`, `effectiveFrom`, `createdAt`, `createdBy`, `note` (500 caractères au plus), `fingerprint`, `terms`, `cancelledAt`/`cancelledBy`, `pending` (quatre yeux, `Boolean`, jamais `null`), `approvedAt`/`approvedBy`. Les termes sont **imbriqués** sous `terms` (et non à plat comme dans l'exemple du § 2.2) : le corps de `POST …/contract/versions` est déjà `{terms, effectiveFrom, note}`.
- `ContractTerms` : `validity`, `enforcement` (`enforce` par défaut, `warn`), `environments`, `services` (`uses`, `gdownDatabase`, `distributed`, `distributedLocks`, `sleep`, `extraPorts`, `nas`, `routeKinds`, `memory` : mémoire des assistants IA de l'organisation), `quotas` (`apps`, `reservedMemoryMb`, `replicasPerApp`, `memoryMbPerReplica`, `scratchMbPerReplica`, `distributedQuotaMbPerApp`, `defaultDistributedQuotaMb`, `storageMb`, `domains`), `quotasByEnv`, `ha` (`spreadNodes` 1 à 8, `antiAffinity` `preferred`/`required`), `apps` (surcharges par application, 64 au plus : `memoryMbPerReplica`, `replicasPerApp` et `ha` peuvent élargir, `scratchMbPerReplica` et `distributedQuotaMbPerApp` seulement resserrer), `pricing` (`currency`, `priceList {id, version | follow}`, `subscription {monthly, perApp, perHaApp}`, `discountPct`, `minimumMonthly`, `overrides [{unit, dims, env, per, price | tiers, included, discountPct}]`), `budget` (`monthly`, `thresholdsPct` 1 à 500 %, 5 au plus, `forecast`). **Champ absent : pas de plafond / tout est permis ; liste vide : rien.** `quotasFor(env, app)` = `quotas` ⊕ `quotasByEnv[env]` ⊕ `apps[app]` ; `haFor(app)`.
- `PriceList` (`id`, `name`, `currency` ISO 4217 immuable, `versions`), `PriceListVersion` (`version`, `effectiveFrom`, `createdBy`, `note`, `lines`), `PriceLine` (`unit`, `dims`, `per`, `price`), `PriceList.effective(t)`.
- `Violation` : `code` (`Violation.CODES` : `organization-unknown`, `organization-suspended`, `organization-required`, `environment-not-allowed`, `service-not-allowed`, `gdown-database-not-allowed`, `distributed-not-allowed`, `locks-not-allowed`, `sleep-not-allowed`, `ports-not-allowed`, `nas-not-allowed`, `route-kind-not-allowed`, `route-app-foreign`, `replicas`, `memory-per-replica`, `scratch-per-replica`, `distributed-quota`, `apps`, `reserved-memory`, `storage`, `domains`, `concurrent-quota`), `field`, `limit`, `used`, `requested`, `value`, `source` (`organization` ou `top`), `message` (phrase en français, pour `violations`).
- `Contracts` : `effective(versions, t)` (version non annulée et approuvée de plus grand `effectiveFrom ≤ t`, à égalité le plus grand numéro ; pure, l'instant vient de l'appelant), `state(v, versions, t)` (`scheduled`, `active`, `superseded`, `cancelled`, `pending`), `next(versions, t)`, `canonical(terms)` et `fingerprint(terms)` (`sha256:<hex>` du JSON canonique **des termes seuls** : clés triées, nuls omis, sans espace ; ni numéro, ni date d'effet, ni auteur : deux clusters qui importent la même version ont la même empreinte). `Canonical.json` parcourt les records par leurs composants.
- `TermsValidator` : `validate(terms)`, `validateLines(lines)`, `validateLink(terms, priceList)` (liste inconnue, version épinglée inconnue, devise différente) ; toutes les erreurs, en français. Bornes : 64 surcharges par application, 200 lignes de prix, 3 dimensions, 5 seuils, `higgs` jamais permis dans `services.uses`, unité hors catalogue, indicative ou interne refusée.
- `Decimals` : montants en chaînes décimales (9 décimales au plus, jamais de `double`), décimales des devises ISO 4217 (2 par défaut, 0 pour JPY, KRW…, 3 pour KWD, BHD…), arrondi au demi supérieur.
- `Pricing.value(currency, daysInMonth, sections)` : valorisation pure d'un mois (§ 6.1), une `Section` par version de contrat (part du mois `share`, termes de tarification, lignes de la liste employée, usage, jours de la part fixe) → `Statement` (lignes par unité, dimensions et environnement, paliers, montants arrondis à l'unité mineure, part fixe, minimum, total). Règles détaillées dans la Javadoc ; quantités converties arrondies à 9 décimales, `included` et bornes des paliers multipliées par la part, unité sans prix montrée « non tarifée » (montant 0), unité indicative ou interne ignorée.
- **Jeu d'essai commun** `sdk/src/test/resources/contracts/pricing-vectors.json` (10 vecteurs : liste seule, surcharges et paliers, minimum, changement de version au milieu du mois, unité non tarifée, JPY, demi-centime, environnement, part fixe par application, octets et stockage) : le calorimètre et Prism doivent rendre les mêmes montants.
- `io.gluonify.plasma.usage` : `UsageCatalog` (catalogue fermé : les unités de `metering.md` § 3.1 et d'`analysis.md` § 10, service, grandeur, `billable`/`indicative`, `internal`, dimensions énumérées), `UsageUnit`, `Quantity` (grandeurs de base et de facturation : `MB-second` → `MB-hour`, `GB-hour` (÷ 3 686 400) ; `second` → `minute`, `hour` ; `unit` → `thousand`, `million` ; `byte` → `MB`, `GB` (2³⁰) ; `GB-hour` → `GB-month` (720 h) ; `unit-second` → `unit-hour`, `unit-month`). La phase 0 de metering n'existant pas encore, C0 livre ce catalogue.

## Contrat d'usage `/q/usage` des composants (`gluonify-usage/1`, depuis le 2026-10-17)

Paquet `io.gluonify.plasma.usage` (SDK, Java 17 ; plan [gluonify-codex/plans/usage-mcp.md](https://github.com/gluonify/gluonify-codex/blob/main/plans/usage-mcp.md) § 3 et § 5.2) : ce que chaque composant de la plateforme répond à `GET /q/usage` pour que Higgs agrège le CPU et la mémoire par application et par composant, et que l'outil MCP `usage` de Gauge les montre. Ce n'est **pas** une base de facturation (metering.md) : tout ce qui n'est pas `measured` est indicatif.

- `ProcessUsage` : lecture pure (aucune dépendance) du processus courant : CPU **cumulé** en secondes (`utime + stime` de `/proc/self/stat`, jamais un pourcentage : l'appelant fait les différences, une valeur qui diminue est une remise à zéro), mémoire résidente (`VmRSS`), fils, durée de vie, tas si le runtime le sait ; cgroup v2 du processus (`0::/chemin` de `/proc/self/cgroup` sous `/sys/fs/cgroup`, racine en conteneur : `memory.current`, `cpu.stat usage_usec`, `memory.max`). Chemins injectables pour les tests ; ne lève jamais : un fichier absent ou illisible (macOS, cgroup v1) donne un champ absent, jamais une valeur inventée.
- `UsageReport` (records Jackson 3, champs absents omis) : `contract`, `component`, `version`, `instance`, `node`, `at` (ms), `process {cpuSecondsTotal, memoryBytes, memoryKind (rss|pss|cgroup), heapBytes, threads, uptimeSeconds}` (obligatoire), `cgroup {cpuSecondsTotal, memoryBytes, memoryLimitBytes}` (facultatif), `attribution` (`none`, `measured`, `estimated`, `prorata`), `byApp [{app, uuid, cpuSeconds, memoryBytes, basis, unit, storageBytes}]` (vide si `none` ; l'application est identifiée par son UUID, le nom sert à l'affichage), `unattributedShare {cpuSeconds, memoryBytes}`, `storageBytes` (see "Occupied storage" below). `UsageReport.of(...)` assemble une réponse valide : parts triées (mémoire, puis CPU), ramenées au prorata si leur somme dépasse le processus, part non attribuée calculée pour que **Σ `byApp` + `unattributedShare` = `process`**. **Plafond : 500 lignes d'applications réelles (`MAX_APPS`) plus une seule ligne `_other`** (`OTHER`) qui regroupe le reste et ne compte pas dans les 500 ; réponse de 256 Kio au plus (`UsageContract.MAX_BYTES`). Contrat additif : un lecteur ignore les champs inconnus ; `contract` ne change que pour une rupture.
- `UsageContract.check(JsonNode | byte[])` : le validateur, liste des écarts en français (vide = conforme) ; utilisé par les tests de tous les dépôts et par `check-usage-contract.sh` (chamber). Refuse : champ obligatoire absent, `attribution` inconnue, `none` avec des lignes, `basis` hors `measured|estimated|prorata` (jamais `none` sur une ligne), plus de 500 lignes ou deux `_other`, somme des parts différente du total, taille dépassée ; `storageBytes` that is not an integer ≥ 0, rows carrying `storageBytes` without the top-level total, or a rows' sum above it (messages of the storage checks in English).
- `UsageContributor` (CDI bean, optional): `byApp()` (or `byApp(process)`, which receives the process the resource has just measured, to split its totals pro rata without reading `/proc` again) , `attribution()` (default `estimated`) and `storageBytes()` (default null: the total stored by the component, from a cache, reported even without rows) d'un composant qui sait attribuer (gdown par base, rup par espace de noms, higgs par ingress…) ; lecture de compteurs ou de valeurs en cache, jamais un parcours de disque. Plusieurs beans : la confiance la plus faible gagne ; un bean en panne ramène la réponse à `none` sans la faire échouer. Sans bean : `attribution: none`, état valide.
- `UsageResource` (`@Path("/q/usage")`, prête à l'emploi) : **jamais anonyme** (401 sans identité, 403 sans rôle), `Cache-Control: no-store`, pas de secret ni de valeur de configuration dans le corps.

**Activation explicite** (décision du 2026-10-17) : le SDK n'est pas un archive de beans, le point d'accès n'apparaît que dans le composant qui l'a demandé ; le préfixe `/q/` reste bloqué par l'ingress public en PRD (`ManagementPaths` de Higgs).

| Propriété | Défaut | Rôle |
|---|---|---|
| `quarkus.index-dependency.plasma-sdk.group-id` / `.artifact-id` | absent | `io.gluonify.plasma` / `gluonify-plasma-sdk` : active la découverte de `UsageResource` (et des beans du SDK) dans ce composant |
| `gluonify.usage.component` | `quarkus.application.name` sans le préfixe `gluonify-` | le champ `component` de la réponse |
| `gluonify.usage.instance` | absent | le champ `instance` (nom de l'instance placée par Higgs) |
| `gluonify.usage.node` | absent | le champ `node` |
| `quarkus.application.version` | `unknown` | le champ `version` |

Rôles : `gluonify:usage:read` (commun, celui de Higgs) ou `gluonify:<produit>:usage:read` (appel direct d'exploitation, `<produit>` = le `component`) ; à déclarer dans la configuration des rôles de chaque composant.

**Jar de tests** (`gluonify-plasma-sdk:test-jar`, géré dans le POM parent) : `UsageContractTests`, classe abstraite dont chaque composant hérite en fournissant `authorizedBody()`, `statusWithoutToken()`, `statusWithoutRole()` et **`secrets()`** (abstraite à dessein : les valeurs sensibles de sa configuration de test, au moins une ; une liste vide fait échouer le test, qui serait sinon tautologique) ; six contrôles identiques partout : réponse conforme, 401 sans jeton, 403 sans rôle, taille bornée, aucun secret dans le corps, and `storageIsConsistent` (since 2026-10-17: integers ≥ 0, rows' sum ≤ total; a component that stores data overrides `storesData()` to return true, and its report must then carry `storageBytes`).

**Occupied storage** (additive change of 2026-10-17, the contract stays `gluonify-usage/1`: a reader ignores unknown fields, an older report without it stays valid): optional `storageBytes` (`Long`, bytes) at the top level of the report (total stored by the component: disk, measured or from its last snapshot, never a disk walk in `/q/usage`) and on each `byApp` row (stored for that application). Absent (never `0` made up) when the component stores nothing. The rows' sum is at most the total: the remainder is stored but attributed to nobody (objects without an application). Storage never enters the CPU and memory split, and it is reported even with `attribution: none` (no row, e.g. Rup over a window without I/O: the total only). `UsageReport.of(..., shares, storageBytes)`: total kept without rows, rows beyond 500 add their storage to `_other` (a contributor's own `_other` row joins it), a total below the rows' sum is raised to it, no total and rows with storage: their sum. `UsageResource` sums the `storageBytes()` of the contributors. Example:

```json
{"contract":"gluonify-usage/1","component":"rup","at":1760700000000,
 "process":{"cpuSecondsTotal":120.0,"memoryBytes":268435456,"memoryKind":"rss"},
 "attribution":"prorata",
 "byApp":[{"app":"shop","cpuSeconds":8.0,"memoryBytes":178956970,"basis":"prorata","storageBytes":5368709120},
          {"app":"blog","cpuSeconds":4.0,"memoryBytes":89478485,"basis":"prorata","storageBytes":1073741824}],
 "unattributedShare":{"cpuSeconds":108.0,"memoryBytes":1},
 "storageBytes":7516192768}
```

**Node usage over the agent channel** (step 3 of the plan, since 2026-10-17): additive messages `Msg.UsageRequest` (control-plane -> node: `id`, optional `apps` = filter by application name, empty = all) and `Msg.UsageReport` (reply with the same `id`: `status` 200 or 500, `node`, `at`, `agent` = the `gluonify-usage/1` contract of the agent's process, `instances` = one `Msg.UsageInstance` line per instance desired on the node: `app`, `uuid`, `state` active|frozen|stopped|absent, `running`, `reservedMb`, `cpuSeconds` (cumulative), `memoryBytes`, `tasks`, `lastKnown`, `measuredAt`), same rules as `Msg.InstanceReport`: a sleeping instance is **never** woken, a stopped one returns its last known values. `usage` family of `Msg.Welcome.features`: only a control-plane announcing it sends the request; an older agent ignores it without replying (timeout on Higgs' side, node `reachable: false`). `UsageResource.report()` is public so the agent can send its contract over that channel, and so is its explicit constructor (component tests with a fake `/proc`, through `QuarkusMock`); `UsageContributor.byApp(process)` receives the measured process. Array `Msg$UsageInstance[]` declared for native images; tests `MsgUsageReportTest` (3), `UsageContributorTest` (2, storage reported without rows).

Image native : `UsageReport`, `Process`, `Cgroup`, `AppShare`, `Share` et le tableau `UsageReport$AppShare[]` sont déclarés dans `reachability-metadata.json` du SDK (gardés par `ContractNativeMetadataTest`). Tests : `ProcessUsageTest` (8 : faux `/proc`, cgroup v2 d'une unité systemd et de la racine d'un conteneur, cgroup v1 ou absent, chemin `..` ignoré, remise à zéro, illisible sans exception), `UsageContractTest` (9, storage included), `UsageReportTest` (8 : `_other`, réduction au prorata, aller-retour Jackson, storage carried and folded, a contributor's `_other` joining the fold, round trip with and without storage), `UsageResourceTest` (11 : les six contrôles communs, rôle du produit, contributeur en panne, confiance la plus faible, fuite de secret détectée).

## Protocole de gluonify-fermion (workflows BPMN et règles DMN)

Paquet `io.gluonify.plasma.fermion` : le contrat WebSocket entre un nœud applicatif et gluonify-fermion. `FermionMsg` (interface scellée, champ `t`) : `Auth` (premier message : jeton Charm d'audience `gluonify-fermion` et version du protocole, jamais dans l'URL), `Hello` (compétences et workflows utilisés, adresse de l'OpenAPI), `Start` (soumettre un workflow ; `organization` facultative, l'organisation de l'exécution posée par un nœud de la plateforme), `Command` (exécuter une tâche : `action` = la compétence, `stepId` facultatif = l'id du nœud BPMN, pour distinguer deux étapes d'une même compétence), `Result` (succès ou échec avec `errorKind` lisible par la machine ; reprend `stepId`, `Result.ok(command, …)` et `Result.failure(command, …)` le font), `Progress` (battement d'une tâche en cours : `correlationId`, `action`, `stepId`, `message` facultatif ; `Progress.of(command, …)` ; fermion repousse l'échéance du résultat et ne renvoie pas la tâche ; un fermion antérieur journalise une erreur de lecture et l'ignore), `Error`. `SkillDescriptor.expectedDuration` (facultative, ISO-8601 : `PT2H`, `P7D`) annonce le plus long silence admis pour une compétence. Les champs `organization` et `stepId` sont facultatifs dans les deux sens : un nœud qui les ignore (gluonify-interfero) reste compatible. Types associés : `SkillDescriptor`, `WorkflowDescriptor`, `SkillParam`, `Translation`, `Language` (en, fr, es, it, de). Le SDK ne contient que le contrat ; le client est le module `fermion-client` (`gluonify-plasma-fermion-client`, paquet `io.gluonify.plasma.fermion.client`) : connexion Quarkus WebSockets Next avec jeton Charm dans la trame `Auth`, reconnexion planifiée avec un connecteur neuf à chaque tentative, file bornée des `Start` pendant une coupure, SPI `SkillHandler` / `SkillHandlerRegistry` / `TaskContext` / `WorkflowUsage` ; voir `fermion-client/README.md` (configuration `gluonify.fermion.client.*`). Les types doivent être listés dans le `Reflection.java` du consommateur (natif).
